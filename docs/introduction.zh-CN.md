# Forthmark 项目介绍

[English](introduction.md) · **中文**

## 一句话定位

**Forthmark 是架在 agent 之上的"项目层"：agent 干活时顺手记下结论，你不用开会话、不用翻文档，就能一眼看清每个项目做到哪、卡在谁、下一步，并且能在面板上把等你处理的事直接处理掉。会话和执行本身，全部交给你自己的 agent。**

## 总结

用 agent（Claude Code 等）推进真实工作时，信息散在两个地方：会话里和 md 文档里。想知道一个项目到哪了，要么打开会话问 agent、让它重读一遍（花 token、要等），要么自己翻一堆 PLAN / TODO / PROGRESS。项目一多、周期一长、再加上等甲方等同事、经常被打断，事情就会悄悄停下来。

Forthmark 不改变你用 agent 的方式。它让 agent 在工作的当下，用几条命令把**结论**记进一份项目状态（任务、等待项、bug、决策、下一步），再把这份状态以面板、菜单栏、终端状态栏和提醒的形式交给你。你在面板上做的决定也会同步回正在进行的会话。整个过程不调用 LLM，不往项目里写任何文件；会话的选择、对话、改代码都还是 agent 自己的事。

## 分点

**看得见**
- 现在在做什么、进度、阶段、下一步，按项目一眼看清
- 卡在谁：等你决定 / 等你去做 / 等甲方 / 等同事 / 等外部，等了几天、卡住了哪些任务
- 推进节奏：最近三周每天有没有动、项目第几天、累计活跃几天、完成与范围的走势
- 文档地图：项目里散落的 md 和脚本按作用分组，进度来源置顶，改过会标"有更新"

**记得住**
- agent 干活时顺手记（命令式，几百 token），hook 兜底检查有没有记
- 被打断时暂停并记下恢复要点，回来一眼看到"停在哪"
- 做完的事可以按文件自动核实，避免"点了做完、其实没做"
- 已解决的等待项、已关闭的 bug、做过的决定都能回看

**动得了**
- 在面板上记下决定、我做完了、对方已回复，自动同步回正在进行的会话
- ＋ 新建项目：建文件夹、接入跟踪、在终端里打开 agent，第一句话由你来说
- ＋ / ▶ / ☰：新会话、回到最近的会话、agent 自己的会话列表（都是 agent 原生功能的快捷方式）

**不打扰**
- 菜单栏一个数字、终端状态栏一行字、超期才通知
- 零侵入：不往项目里写文件，只读 git
- 不调用 LLM；自身开销可见（"工具开销 N+"）

## 详细

### 1. 要解决的痛点

| 痛点 | 具体表现 |
|---|---|
| 想知道进度得开会话问 | 问 agent"做到哪了"，它要重读 md 和 git log，一次几万 token，还要等 |
| md 越来越多，看不清全局 | PLAN / TODO / PROGRESS / 需求散在仓库里，不知道哪份还有用、哪份是最新 |
| 卡在等人，然后忘了 | 等甲方确认、等同事开权限、等自己拍板，埋在文档和聊天里，等着等着就停了 |
| 被打断，回不来 | 做到一半插进来别的事，过几天想不起做到哪 |
| 回来要重新交代背景 | 新开会话又要跟 agent 解释项目现状 |
| 想到点子，开工成本太高 | 开终端、建文件夹、启动 agent、交代想法、再接入管理 |

### 2. 设计理念

1. **项目层，不碰 agent 本身。** 组织单位是项目（git 仓库根目录）和其中的事情，不是会话。会话列表、会话命名、对话、改代码都是 agent 的核心功能，我们不重复。
2. **在知道的那一刻记录，而不是事后总结。** agent 干活时最清楚发生了什么，这时顺手记一条结论成本最低、也最准。我们不读会话内容、不调用 LLM 去总结，所以也不依赖任何 agent 的内部格式。
3. **辅助，但克制。** 只交给 agent 两样东西：用户自己说的话和项目的事实状态；不替用户下指令，不重复给它已经知道的东西。
4. **零侵入。** 所有数据在 `~/.forthmark/`，不往项目里写任何文件，git 只读。
5. **看得见，但不打扰。** 信息出现在你本来就在看的地方（菜单栏、终端状态栏），只有超期才提醒。
6. **成本透明。** 不调用 LLM；hook 拦截造成的额外轮次精确统计并显示。

### 3. 怎么工作

```
你的 agent（Claude Code …）
  ├─ 会话开始：hook 注入记录规则 + 项目当前状态（接回旧会话时不重复注入）
  ├─ 干活时：顺手运行 forthmark.py op …（加任务、记等待、修 bug、做决定、暂停…）
  ├─ 你每次发消息：hook 把你在面板上的操作同步给它
  └─ 每轮结束：hook 检查状态是否跟上（没跟上就请它补记）、自动核实、归档、刷新面板
                         │
             ~/.forthmark/projects/<项目>/status.json
                         │
  面板（菜单栏小窗 / 大窗 / 浏览器）· 菜单栏数字 · 终端状态栏 · 系统通知
                         │
  你：看进度、处理等你的事、新建项目、打开会话 ──→ 同步回 agent
```

### 4. 功能清单

| 模块 | 功能 |
|---|---|
| 现在在做 | 进行中的任务和修复中的 bug（插队的标 ⚡）、暂停中的任务及恢复要点、进行太久提醒、最近完成 |
| 卡在谁 | 按等谁分组、按能解锁多少任务排序、等别人超 3 天提示该催、催办话术一键复制、记下决定 / 我做完了 / 对方已回复、已解决的可回看 |
| 下一步 | 当前没被卡住、最值得做的事 |
| 推进节奏 | 最近 21 天活跃格子（从项目开始那天画起）、项目第 N 天 / 累计活跃、完成与总任务的累计曲线 |
| 任务 / Bug | 进行中 / 暂停 / 待办 / 已完成，被卡住的直接显示卡在什么并可跳转；Bug 的已关闭列表 |
| 推进动态 | 时间线，你不在时的变化标"新" |
| 文档 | 文档地图、进度来源、作用说明、标签 / 备注 / 置顶 / 隐藏、预览（独立窗口） |
| 菜单栏应用 | 计数、小窗（自适应高度）、大窗、开机自启、通知 |
| 终端状态栏 | 当前任务、等你几项、暂停、进度 |
| 入口 | ＋ 新建项目；＋ / ▶ / ☰ 新会话 / 最近会话 / 会话列表 |

### 5. 不做什么

- 不做会话管理（列表、命名、搜索）——agent 客户端做得更好
- 不调度、不并行编排多个 agent
- 不替用户下指令，不替 agent 做判断
- 不读会话内容，不调用 LLM
- 不往项目里写文件，不碰项目的 git
- 不做完整的项目管理（权限、多人协作、甘特图）

### 6. 和 agent 客户端的关系

Claude 桌面版、Codex 等客户端以**会话**为单位，擅长对话、看改动、管理会话；Forthmark 以**项目和事情**为单位，补的是跨会话、跨天的项目状态，以及"等待"这件客户端没有的事。两者不是替代关系，可以叠加使用：用哪个客户端推进都行，项目状态在一个地方。

### 7. 适合谁

| 更适合 | 直接用 agent 客户端可能就够了 |
|---|---|
| 多个项目并行、周期长 | 一两个项目、节奏单一 |
| 经常卡在外部（甲方、同事、审核） | 没有外部依赖 |
| 经常被打断、切换 | 很少切换 |
| 不想为了看进度开会话、花 token | 不介意随时问 agent |

### 8. 现状与限制

早期预览（v0.1）：

- 完整支持 **macOS + Claude Code（命令行）**；Claude 桌面版的 Code 标签理论上共用同一份配置，尚未验证
- Codex / Cursor 等可以用"新建项目 / 打开会话"的快捷入口（命令可配置），状态记录要等 MCP 入口
- Windows：计划在 v0.1 之后出预览版（核心记录、hook、浏览器面板、状态栏）
- 中英文界面，跟随 macOS 系统语言
- 完整的支持范围见 [README](../README.zh-CN.md)「支持范围与限制」
